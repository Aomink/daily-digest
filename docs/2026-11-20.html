1. Claude Code 2.1.328:Bedrock等でも auto mode、MCPフックの失敗ブロック

何が起きたか

11/19付。Claude Opus 4.6 / Sonnet 4.6 の auto mode が、Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、Claude apps gateway で使えるようになった。権限モード未設定の対話セッションは auto mode で始まる。mcp_tool フックでも "onFailure": "block" が使える。/code-review は多くのモデルでバグと CLAUDE.md 違反のみを報告し、指摘は Important / Pre-existing / Nit に分類される。

なぜ役立つか

クラウド経由でClaude Codeを使う組織でも、承認待ちの少ない運用が選べる。ただしデフォルトが変わるため、権限運用の見直しが要る。MCPフックが失敗時に処理を止められるので、ガードレール用途で確実性が上がる。

2. Claude Code 2.1.329:/tasks でスケジュール実行や fork を管理

何が起きたか

11/19付。/tasks に、そのセッションのスケジュールタスク、/loop の再開予定、fork が一覧表示され、x キーで確認後に停止できる。信頼ダイアログは、フォルダ内のフックがどこで宣言されているかを警告する。macOSのcomputer useは新しい安全ルールに従い、一部操作の拒否や一部アプリへのアクセス縮小がある。以前のバージョンで保存したスケジュールタスクは、多くの場合、新しいサインイン済みセッションで再設定が必要。

なぜ役立つか

定期実行を使っている場合、更新後に動かなくなる可能性があるため、再設定の確認が必要。一覧と停止操作ができ、動いているものの把握もしやすくなる。リポジトリ内フックの出どころが見えるのは、他人のリポジトリを開く際の安全確認に有用。

3. OpenAI Agents SDK(Python)v0.25.0(期間の境界。11/18付)

何が起きたか

11/18付のリリースで、時刻まで確認できていないため、24時間の外側の可能性がある。beta の Runloop サンドボックスプロバイダが削除された(利用者はワークスペースのデータを退避する必要がある)。RunState がスキーマ1.22になり、ネストしたエージェントツールの承認を出力ガードレール付きで再開できる。OpenAIResponsesCompactionSession の既定モデルが gpt-6-luna になった(model="gpt-4.1" で従来に戻せる)。ハンドオフのエラー回復用に opt-in の failure_error_function が加わり、MCP v2 の Streamable HTTP は同時リクエストを扱える。

Runloopを使っている場合は移行が必要。既定モデルの変更は挙動やコストに影響しうるので、固定したい場合は明示指定しておくとよい。
