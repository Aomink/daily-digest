1. 【11/6・期間外】Claude Code 2.1.319

何が起きたか

MCPタスクがターミナルでバックグラウンド実行され、完了すると結果がClaudeに通知されるようになった。待機させたい場合は環境変数 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND を使う。また、許可プロンプトで止まる代わりに拒否して処理を続ける permissions.denyInsteadOfPrompting 設定が追加された。

なぜ役立つか

無人で動かす自動化(定期実行など)で、承認待ちのまま固まるのを避けられる。長いMCP処理中も他の作業を進めやすい。

2. 【11/3・期間外】Claude Code 2.1.317 / Agent SDK hook

何が起きたか

Agent SDKのフックコールバックに onFailure: "block" が追加され、コールバックが失敗したら該当の操作を止められる。ウェブ/シェル呼び出しでアカウントのメールアドレスを送信する前に確認する仕組みも入った。

なぜ役立つか

安全確認用のフックが落ちたときに素通りしてしまう事態を防げる(フェイルクローズ)。

Claude Code changelog(公式)

3. 【11/2・期間外】Claude API「Message threads」(ベータ)

何が起きたか

会話をサーバー側に保持し、以降のリクエストは新規メッセージだけ送れる。ベータヘッダ message-threads-2026-08-12 で有効化。スレッドは最後のリクエストの5分後に失効し、最長1時間以内に削除される。

なぜ役立つか

長い会話やエージェントのループで、リクエストサイズと最初のトークンまでの時間を減らせる可能性がある。5分で失効する点は設計時に注意。

4. 【11/5・期間外】Claude API の IP許可リスト(ベータ)

何が起きたか

組織管理者がAPIアクセスを許可するIPアドレス/CIDR(組織あたり最大1,000件)に制限できる。リスト外からのリクエストは拒否される。

なぜ役立つか

APIキーが漏れても使える場所を限定でき、エージェントを動かす固定IPの環境がある組織では防御を一段足せる。
