1. Messages API に「Message threads」(ベータ)

何が起きたか

11/2付。会話をサーバー側で保持し、2回目以降は新しいメッセージだけを送れるようになった。ベータヘッダは message-threads-2026-08-12。スレッドは最後のリクエストから5分で失効し、最終利用から1時間以内に削除される。ZDR(ゼロデータ保持)の対象外と記載されている。

なぜ役立つか

長いエージェントループで毎ターン全履歴を再送する必要がなくなり、リクエストが小さくなって初回トークンまでの時間も短くなる。ただしZDR対象外なので、データ要件のある案件では事前確認が必要。

2. Claude Code 2.1.317:フック失敗時にブロック、送信前確認など

何が起きたか

11/3リリース。Agent SDKのフックコールバックに onFailure: "block" が追加され、コールバックが失敗したら処理を止められる。Webやシェルのツール呼び出しでアカウントのメールアドレスをネットワーク送信する前に確認する仕組み、/schedule で意図しないコネクタが付く場合の警告も追加。Readツールは「ファイル未変更」スタブを返さなくなり、再読込で内容が返る。claude -p はディスクフルやクォータで書き込みに失敗したとき終了コード1を返す。

なぜ役立つか

承認や監査をフックで実装している場合、フック自体が壊れても素通りしない設計にできる。CIで claude -p を使う場合、書き込み失敗を検知しやすくなる。

3. Claude Agent SDK for Python 0.2.177

何が起きたか

11/3リリース。HookMatcher に on_failure が追加され、"block" を指定するとコールバックが例外を出す/None を返す/CLIに拒否される値を返す場合に処理をブロックする(既定は "continue")。古いCLIと組み合わせると CLIConnectionError になる。同梱CLIは2.1.317。

なぜ役立つか

自作エージェントで権限チェックや危険コマンド検査をフックにしている場合、フェイルクローズ(失敗時は止める)にできる。更新時はCLIとSDKのバージョン整合に注意。
